# Codex 会话阅读器

本地运行的单页 Web 应用，把 Codex CLI `/export` 导出的 Markdown 文件还原为易读的用户与 Codex 对话。适合回看被大量工具输出打断的长会话。

## 启动

需要 Node.js 20 或更新版本。

```bash
npm install
./scripts/start.sh
```

浏览器打开 **http://127.0.0.1:4173**。在 WSL 中启动后，也可以用 Windows 浏览器访问 **http://localhost:4173**。

服务启动时会构建前端；页面会列出项目根目录中的 Codex 导出文件和本机缓存，并自动恢复上次打开的会话（包括手动导入的文件）；首次使用时打开目录中最新的文件。当前目录中的示例可直接阅读，原文件不会被修改。

使用以下脚本管理后台服务（Linux / WSL，需要 Bash 和 `flock`，Ubuntu 默认提供）：

```bash
./scripts/start.sh     # 构建前端，后台启动；关闭当前终端后继续运行
./scripts/status.sh    # 查看 PID、访问地址、健康状态和日志位置
./scripts/stop.sh      # 停止服务；重复停止也可正常退出
```

脚本可从任意工作目录调用，会自动定位到项目根目录。日志保存在 `.run/service.log`，进程和监听地址保存在 `.run/service.json`；这些运行文件不会提交到 Git。`status` 的退出码为 `0`（正常运行）、`3`（未运行）、`1`（异常）。

默认使用 `4173` 端口。重复或并发执行 `start` 会复用现有进程；即使后来改变 `PORT`，也不会为已有的受管实例重复开服务。更换端口时，先停止再启动：

```bash
./scripts/stop.sh
PORT=4321 ./scripts/start.sh
./scripts/status.sh    # 自动读取已记录的端口，无需再次指定 PORT
./scripts/stop.sh
```

启动失败时可查看 `tail -n 50 .run/service.log`。停止前会核对进程的启动时间和入口文件，过期 PID 记录不会导致其他进程被误停。也可以继续使用 `npm start` 在前台运行，按 `Ctrl+C` 停止；脚本能识别同一项目、同一端口通过 `npm start` 启动的服务，自定义端口且没有进程记录时需传入相同的 `PORT`。

## 使用

- 点击 **打开导出文件**，或将文件拖入窗口。支持 `.md`、`.markdown` 和 `.txt`，UTF-8 编码，单文件上限 20 MB；可以同时打开多个文件。成功打开的文件自动保存在浏览器本机缓存，刷新或关闭页面后仍可再次打开。
- **会话文件**将目录文件和缓存文件按会话开始时间从新到旧统一排列，无法识别时间的文件放在最后；列表每批显示 50 个，点击 **显示更多会话** 继续查看，当前会话始终可见并保持时间顺序。刷新按钮重新扫描项目目录，也会重新读取当前目录文件；文件内容变化后保留旧缓存作为独立会话。
- 重复导入按文件内容去重：即使文件改名或修改时间不同，内容完全一致也会直接复用已有会话，不增加文件副本；同名但内容不同的文件会分别保存。
- 点击左上角 **codex** 返回当前会话顶部，不重新加载页面，当前文件、搜索和阅读视图都会保留。
- 对话条数、工具活动数和文件大小后显示 **会话开始时间**，格式为 `2026年01月10日 13:23:43`，使用浏览器本地时区。时间从默认导出文件名中的 UUIDv7 会话 ID 提取；文件名不含可识别时间时显示“开始时间未知”。
- **对话目录**跳转到指定消息，页面上的 **跳到最后回复** 可直接查看最后一条 Codex 回复。
- 选中会话后，点击 **跳到最后回复** 左侧的 **删除会话**，在弹窗中确认后移除该会话及本机缓存。此操作无法撤销，原始导出文件保留；目录中已删除的文件版本在刷新后也会保持移除，手动重新导入原文件可以再次打开。删除后自动切换到相邻会话，全部删除后显示打开文件入口。
- **对话视图**显示用户和 Codex 消息，连续工具活动默认折叠。点击活动组，再点击某条命令即可查看原始输出。
- **精简视图**保留用户消息和每轮最后一条 Codex 回复；**完整记录**展开所有工具活动。
- **搜索**覆盖所有消息及折叠的工具输出，自动展开并高亮命中内容。计数按匹配的消息或活动条目计算。使用 `Enter` / `Shift+Enter` 切换下一条 / 上一条匹配，`Esc` 清除。
- Markdown 表格、列表、引用和代码块正常排版；常用语言有代码高亮。可以复制消息、代码或源码引用路径，也可以下载原始导出内容。
- 左下角切换深浅主题，窄屏下通过左上角打开侧栏。

快捷键：`Ctrl+O` / `⌘O` 打开文件，`Ctrl+K` / `⌘K` 或 `/` 聚焦搜索。

## 数据与格式

文件解析、搜索和手动导入均在浏览器中完成，文件不会上传。成功导入的文件以及已打开的目录文件保存在浏览器的 **IndexedDB** 中，以原始字节的 SHA-256 指纹作为唯一标识；文件索引和正文分别存储，每份内容只保存一份。重复导入需要在本机读取所选文件以计算指纹，匹配后直接复用缓存，不重复写入正文；原始 UTF-8 BOM 和换行格式会保留。

启动时只读取轻量文件索引和上次打开的会话正文，其余会话在选中时才读取、解析，已切走会话的正文和解析结果不会继续堆积在页面内存中。目录扫描只读取文件头用于识别导出文件，不会预加载所有文件正文；恢复缓存会话无需等待扫描结束。工具输出仍按展开和搜索操作延迟渲染。

缓存属于当前浏览器的站点存储：请使用相同浏览器和访问地址，`localhost`、`127.0.0.1` 或不同端口的缓存互不共享。清除站点数据、隐私模式结束或浏览器回收存储可能移除缓存，请保留原始导出文件。缓存不可用或空间不足时，页面会显示提示，仍可在本页打开和切换文件。主题、阅读视图和上次选择的会话标识继续保存在 `localStorage` 中。

Node 服务只负责静态资源与项目根目录内导出文件的读取，默认监听 `127.0.0.1`。没有云端服务、统计代码或运行时 CDN 依赖，安装依赖后可以离线使用。Markdown 经过清理，远程图片不会自动加载；点击外部链接或“打开图片”时才会访问对应网站。本地源码链接用于复制路径，不会将电脑上的其他文件暴露给网页。

主要适配以下 `/export` 结构：

````markdown
# Codex conversation

## User

用户的提问。

## Assistant

Codex 的回复。

## Activity

    $ command
    command output
    ✓ • 12ms
````

同时识别 `System`、`Developer` 和 `Tool` 标题。支持 CRLF、UTF-8 BOM、反引号/波浪号围栏代码块和缩进代码；代码块中的角色标题不会被误切分。根目录自动扫描要求文件以 `# Codex conversation` 标题开头；没有这一总标题、但包含角色标题的文件可以手动打开。

导出正文未提供每条消息的可靠时间和回复通道；会话开始时间来自默认文件名中的会话 ID，不使用文件修改时间或缓存写入时间代替。“本轮最后回复”按每次用户提问后最后一条 Assistant 消息判断。对于 Markdown 原文中位于代码块外、完全同名的 `## User` / `## Assistant` 等标题，格式本身无法区别于消息边界。

## 开发与验证

```bash
npm run dev           # 监听前端源码并自动构建；在浏览器中刷新查看
npm run build         # 生成 public/assets
npm test              # 解析、原文保真、目录读取与单实例测试
```

浏览器交互测试：

```bash
npx playwright install chromium
npm run test:browser
```

Linux 如缺少 Chromium 运行库，可按 Playwright 的提示安装系统依赖（`npx playwright install-deps chromium`）。测试使用独立的 `4175` 端口、隔离的浏览器存储和合成示例，覆盖缓存恢复、内容去重、按需读取、目录更新与存储失败，不修改真实导出文件；用户提供的示例存在时，也会验证其 40 条记录的解析与展示。

工程结构：

```text
server.mjs           本地只读服务、文件扫描、重复启动检测
src/parser.js        纯函数 Markdown 对话解析器
src/markdown.js      Markdown 渲染、代码高亮、内容清理
src/app.js           文件载入、搜索、导航与视图交互
src/session-cache.js IndexedDB 文件索引、正文缓存与内容去重
src/styles.css       响应式界面与深浅主题
public/              页面入口与本地构建产物
scripts/             start.sh / stop.sh / status.sh 服务管理，以及构建和开发脚本
tests/               解析/服务测试、浏览器交互测试
```

`codex-session-*.md` 默认在 `.gitignore` 中，避免将可能包含私密信息的导出文件提交到版本库。
